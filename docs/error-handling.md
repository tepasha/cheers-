# Обробка помилок застосунку

Помилки всіх екранів показуються через `ErrorScreen` із котиком, копіюванням діагностики та підтримкою.
Не додавайте окремі error-alert, банери чи червоні повідомлення під формами.

- `reportAppError(error, { message })` передає помилку єдиному обробнику; `message` — коротке локалізоване пояснення. Оригінал і код помилки доступні для копіювання.
- `dialogs.error(message, error)` — той самий шлях для компонентів, які вже використовують сервіс діалогів.
- `Button` та `IconButton` перехоплюють синхронні винятки і відхилені Promise. Асинхронний обробник має повертати Promise, а не відкидати його через `void`.
- Для фонових запитів створюйте `captureAppErrorReporter(options)` **до** запуску операції. Репортер ігнорує відповіді попередньої сесії. Чинні `captureSession` та прапорці скасування також залишаються обов'язковими.
- `retry` задавайте для безпечного повтору читання або вже створеної операції outbox. Без callback кнопка повертає до поточної форми; введені дані та відкритий sheet зберігаються. Видалення акаунта чи нова публікація автоматично не повторюються.
- `restart: true` перезапускає дерево інтерфейсу, наприклад для відновлення завершеного Firestore listener. Render-помилки теж перезапускають дерево.

Єдиний `ModalHost` має пріоритетний вміст для помилки, тому вона покриває також відкриті sheets без другого native Modal. Усе дерево, включно з модальними компонентами, перебуває всередині render boundary.

Глобальні JS-винятки й необроблені Promise перехоплюються у браузері та React Native/Hermes. Це не перехоплення аварій нативного процесу чи ОС, коли JavaScript уже не виконується.

Підтвердження дій, успішні повідомлення, статус offline/очікування синхронізації та штатні відмови користувача залишаються своїми UI-станами. Помилки копіювання чи відкриття підтримки обробляються на самому `ErrorScreen`, щоб не створювати рекурсивні екрани помилки.

Діагностика не зберігається в Redux/persist. Паралельні помилки не замінюють повідомлення, яке копіюють: різні збої стають у обмежену чергу, повтори об'єднуються. Зміна акаунта чи покоління сесії очищає її.
